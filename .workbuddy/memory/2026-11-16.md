## 「整句没看懂」把上一句一起解释 —— 根因已定位（只读诊断，未改代码）

- 线上 `explain_events` 确凿证据：最新一条 `kind=explain, ask_kind=whole_sentence, word="I don't need to explain what features... harness. pi comes with most creature comfort"`；上一条 `kind=lookup, word=comforts`。即发给 AI 的 word 混进了前一句（库里 word 截到 120 字符属展示截断，不影响发给 AI 的完整文本）。
- 链路：
  1. `Reader.tsx:1015-1019` comforts 是已收词/已批注 → 点它走 `recallPick()` 回看分支；
  2. `Reader.tsx:731-745` `recallPick()` **不设置 `pick.signals`**（新点词 1036 / 拖选 1085 都设置了）；
  3. `Reader.tsx:1512-1521` `aiContextOf()` 因该句生词密度 ≥75%（comes with / most / creature comforts / used 均为已收词）→ `sentence.ts:150-158` 把上一句拼进 `prefix`，并置 `withPrevSentence:true`；
  4. `Reader.tsx:1704-1706` `sentence = pick.signals?.sentence || (aiContext.prefix + quote + aiContext.suffix)` —— signals 缺失走了 fallback，上一句进了 sentence；
  5. `Reader.tsx:1717-1726 / 1789-1790` 「整句没看懂」把 `word: sentence`、`prefix:""`、`suffix:""` 发给 AI → AI 解释了两句。
- 最小修复方案：`recallPick()` 内用 `selectionSignals(para.content, a.start, a.end, source)` 补上 `signals`，让 sentence 走纯当前句；顺带评估是否把 fallback 从 `aiContext.prefix + quote + suffix` 改为按 anchor 从段落重算句子（`aiContext.prefix` 语义是「给 AI 的上下文」，不该当作「所在句」来源）。未执行，等用户确认。

### 更深根因（推翻上面「补 signals 即可」的方案）

- 线上 `contexts` 实测：`paragraph_id=a50ef143...`, start=113/end=121, quote=comforts, **prefix="I don't need to explain what features you should expect from a coding agent harness. pi comes with most creature "**（含上一句），suffix=" you're used to from other tools:"。
- 段落原文**是单行，没有换行**：replace(char(10)) 无 `<NL>`；全文 154 字符，两句之间是 ". "（句号+空格）。用户以为是换行，实为视觉折行 + 冒号结尾。
- **真正根因**：`Intl.Segmenter("en",{granularity:"sentence"})` 把 `". pi "` 判定为缩写（像 Mr./etc.），整段返回 1 个 span。本地实测：
  - `"harness. pi comes..."` → 1 句（错）
  - `"harness. Pi comes..."` / `". The pi comes..."` / `". It comes..."` → 2 句（对）
  - 即句号后跟 2–3 个小写字母会被 Segmenter 误判为缩写。
- 后果：`splitSentences` 返回整段一个 span → `buildAnchor` 的 sentStart=0 → prefix 含上一句；`selectionSignals.sentence` 也是整段；`aiContextOf.core` 也是整段。所以**补 signals 不够**（signals.sentence 本身错），必须修 `splitSentences`。
