## 首页筛选 chip：数量显示 bug

用户报「难度 A21 / B22 是什么，不应该是 A2 / B2 吗」。根因：`TextList.tsx` 的 `renderChip` 用 `{label}{count !== undefined ? \` ${count}\` : ""}` 把等级和数量用一个空格拼成文本，13px 粗体 `nowrap` 下 `A2` + `1` 视觉粘连成 `A21`（B2 2 → B22）。

**第一次改错了方向**：把数量做成 `.duo-filter-count` 独立徽标（CSS + JSX）。用户打断纠正：「分类以及难度选中的时候，不应该把数量放在这里，就算要放也不能放在这里，要放在别的地方」。教训同前 —— 用户要的是最小视觉修正，不要顺手加新样式/结构。

**最终方案**：chip 只渲染纯标签文字（`A2` / `B2` / `未分类` / `技术文档`），数量移到 `title` 悬停提示（如 `A2 · 1 篇`）。`globals.css` 全部回退（无残留），`TextList.tsx` 仅 1 行改动；计数、筛选、选中、事件零改动。

验证：typecheck / 236 单测 / build + 重启通过；Playwright 实测标签 `["A2","B2"]`、悬停提示 `["A2 · 1 篇","B2 · 2 篇"]`、chip 内数量徽标 0 个。此改动**尚未提交**（上一轮 `def771e` 已推送，与此无关）。

## 首页两栏标题对齐

用户指出「导入文本」和左边的「我的文本」没对齐。根因：`src/app/page.tsx:65` 用 `grid lg:grid-cols-[1fr_340px] gap-7 items-start`，两栏容器顶部都在 y=185；左栏首行是 TextList 的裸 `.duo-section-title`，右栏首行是 `ImportForm` 的 `.duo-card p-6`（24px 上内边距）里的 h2 → 右标题被推下 **25px**。

纯 CSS 修复（收口层末尾，零 JSX / 零逻辑）：
```css
@media (min-width: 1024px) {
  main > div > [class*="grid-cols-[1fr_340px]"] > div:first-child > div:first-child > .duo-section-title:first-child {
    padding-top: 25px;
  }
}
```
只在 lg 双栏生效；窄屏单栏不补；同页统计卡的第二个 `.duo-section-title` padding 仍为 0（未误伤）。

验证：typecheck / 236 单测 / 清缓存 build + 重启通过；Playwright 用真实产物复测，1200px 两标题文字 top 均为 214（**差 0px**），900px 时 `padding-top: 0px`。

**验证踩坑（下次注意）**：① 构造的 DOM 必须包 `<main class="flex-1">`，否则 `main > div > ...` 选择器不命中；② `padding-top` 撑高元素但 `getBoundingClientRect().top` 不变，必须用 `Range.selectNodeContents()` 量文字位置，量元素边框会得到「没修好」的假结论。
