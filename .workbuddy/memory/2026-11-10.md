## 阅读页右栏改为「单滚动 + 只放当前释义」

- 需求：全页只保留 window 一个滚动；右栏只放当前这一次的一句话释义；删掉右栏「已存批注」列表；想看之前的释义就点正文里带绿色标记的词/短语。
- 实现：`Reader.tsx` 删 `rf-annots` 列表 UI / `showAnnotations` state / `openAnnotation` / `removeAnnotation`；**保留** `loadAnnotations`、`annotations`、`rangeKeyByPara`（绿色下划线 `w-annotated` 的数据源）、`glossCacheRef` + `savedGlossFor`（旧释义缓存）、`forgetGloss`。
- 回看链路（改动前就存在，已核对）：点标记 → `pickWord`/`pickRange` 命中 `savedGlossFor` → `initialGloss` + `fromAnnotation` → `PickCard` 直接 `aiStatus="done"` 摊开；`shouldAutoExplain` 对 `hasInitialGloss`/`fromAnnotation` 返回 false，不重新请求模型。
- `globals.css`：`top: calc(var(--rf-bar-h) + 16px)`、`max-height: calc(100vh - var(--rf-bar-h) - 32px)`，修掉 P19 加常驻顶栏后遗留的顶部 38px 遮挡；删掉整个 `.rf-annots*` / `.rf-annot-*` 样式块。

## 踩坑与决策

- **`overscroll-behavior-y: contain` 不能用在这里**：实测它会把鼠标停在右栏时的滚轮事件直接吞掉（window.scrollY 不动），反而复现"滑不动"。用户要的是单一滚动，已去掉；右栏 `overflow-y:auto` 仅作超长释义兜底。
- **Turbopack 全局 CSS 增量缓存坑**：改 `globals.css` 后 `npm run build` 产物仍是旧规则（CSS 文件名和内容都不变）。必须 `rm -rf .next/cache` 再 build 才生效。`docs/ARCHITECTURE.md` 12.6 记过同类问题。
- 本机 launchd `com.readflow.server` 跑的是 `next start -p 3000`（生产构建），源码改动必须 build + `npm run service:restart` 才生效。`kickstart -k` 在本机可正常执行（与 `launchctl bootstrap` 的 EIO 限制不同）。
- 配套同步：3 个 e2e 脚本从 `.rf-annot-open` / `.rf-annots-list` 改为断言/点击 `[data-pid] .w.w-annotated`；README / ARCHITECTURE / explain-policy 注释里的「列表回看」措辞改为「点正文绿色标记」。

## 验证

`npm run typecheck` 通过；`npm test` 201/201；`npm run build` 通过；Playwright 用运行时 CSS 复现 DOM：右栏 sticky 到 70px（顶栏底 54px，不遮挡）、`clientH==scrollH` 无独立滚动条、历史列表节点 0、右栏上滚轮 +400 → `window.scrollY` 1200→1600。三个 e2e 脚本 `node --check` 通过，但未实跑（需要 E2E_USER/E2E_PASS，库里只有 `syuan` 账号）。

## 第二轮：已存批注升为一等交互单位（同日）

用户确认：① 颜色用主题绿 `--duo-green`（或稍淡），不要半透明浅线；② 点短语里的某个词 = 纯回看整条短语的旧结果，**不发任何新请求**（词典也不查）。理由：用户点那个词说明当初那条 AI 答案没把它讲清楚，是答案质量问题，不该用「再查一遍」生成另一条答案。**AI prompt 本轮明确不动**。

- `globals.css`：`.w-annotated` → `inset 0 -3px 0 var(--duo-green)`（`.w-anchor` 同步 3px）；新增 `.w-ann-hover` 整条连续浅绿底 + 两端圆角。平时不铺常驻底色，保持 P22「一种底色」约定。
- `renderTokens` 的 `rangeKey` 扩成 4 段：`批注区间|选中|拖动预览|悬停区间`；`rangeKeyByPara` 统一生成 4 段（只有涉及段落的 key 变化，其它段落字符串不变 → memo 不失效）。
- `Reader.tsx`：新增 `hoverAnn` state + `onBodyMouseOver`（用 `[data-s]` 统一取词 / 词间空白，避免鼠标经过短语中间空格时高亮闪烁）+ `onMouseLeave` 清除；`pickWord` 命中**含空格的短语批注**时用原锚点重建 pick、带 `initialGloss`/`fromAnnotation`/`contextId` 并直接 `return`，跳过 `ensureAnnotation`；单词批注仍走原路径（查词典 + 摊开已存释义）。
- `PickCard` 加 `recall = fromAnnotation && initialGloss`：useEffect 直接 return（不发 `/api/dict`、不自动问 AI），词典区域隐藏，追问入口保留。**无 aiGloss 的老批注不进 recall**，仍查词典 + 手动入口（README 既有说明）。
- 抽纯函数 `src/lib/annotation-range.ts` 的 `findCoveringRange()`（同段落 + 完整包住 `[s,en)`，重叠取区间最短/起点最早），加 6 条单测，`tsconfig.unit.json` include 同步。

验证：typecheck 通过；`npm test` 207/207（+6）；build + restart 通过；Playwright 用运行时 CSS 实测：hover 时 word1/gap/word2 均为 `rgb(215,255,184)` 且两端圆角连成一条、下划线 `rgb(88,204,2)` 3px；未 hover（等 250ms 过渡结束）只有 3px 实线、无底色。真实页面交互未跑 e2e（需登录态），由用户手动点 `optimization target` 验收。

**再记一次坑**：每次改 `globals.css` 后必须 `rm -rf .next/cache` 再 build，否则 Turbopack CSS 增量缓存会让产物停留在旧规则（CSS 文件名和内容都不变）。
