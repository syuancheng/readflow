## 线上查词偶发超时的诊断（只诊断，未改代码）

用户报 `http://8.148.82.170/texts/14223aef-...` 查词偶尔卡在「查词典中...」很久。已确认：

- 词典不是全量内存：`data/dict/ecdict.db` 115MB 在磁盘，`better-sqlite3` 只缓存连接，走 OS page cache；`idx_ecdict_word_nocase` 已建（Nov 12），`-wal` 为 0。
- 带真实登录态直连 `/api/dict?word=everyone` 等 5 个词全部 HTTP 200、约 100ms；`/api/annotations`、`/api/cards/state`、`/api/learner` 也都在 100ms 左右。
- 正常点击就是 4 个请求：`ensure → dict → annotations → cards/state`，用户截图显示 65/15/10ms。Initiator 是站内 chunk `035gbxsn1paox.js`，**不是浏览器扩展**。
- 用 Playwright 内置 Chromium 对线上做 6 次连续点击：40 个请求全 200、50–60ms、最终 0 pending。注意 Playwright 要用 `requestfinished` 计时；用 `response` 事件配 `request` 事件的对象做 key 会全部误判 pending。
- 异常截图：整页请求（含静态 chunk、RSC 预取、dict、ensure）同时 pending，还多出一个正常流程没有的 `enumerate` 请求；nginx access log 在 15:48:49–16:04:33 之间一片空白，16:04:33 用户导航时这批请求一次性记成 499。服务端 load 0.09、Node 在 ep_poll、CPU 时间几乎为 0、nginx error log 空、无锁。
- 结论：不是词典慢、不是后端慢，是**浏览器/客户端连接层整体卡住**。待用户配合确认：卡住时点开某条 pending 请求的 Timing（Queued/Stalled vs Waiting TTFB）、无痕禁扩展是否复现、是否有别的标签页开着 AI 长流。代码层面 AI 流的取消链路仍不完整（前端新请求不 abort 旧的、服务端 cancel 不传 signal），但这次日志里没有未结束的 `/api/explain`，尚不能定为直接原因。
- 诊断过程临时创建的 session 和 `[DIAG]` 测试文本已全部删除，未改动任何产品代码。

### 决定性证据（16:55 用户 Timing 截图）

- `ensure` 与 `dict?word=unhealthy` 的 Timing 都是：`Queued at 3.79 ms / Started at 3.79 ms / Connection start → Stalled`，**没有 Request sent、没有 Waiting (TTFB)、0 B transferred**。请求在 Chrome 内部就停住，没发给服务器。这解释了 nginx 无日志。

### 根因确认与修复（17:40）

**根因**：前端 fire-and-forget 的 `fetch` 不消费响应体。Next 返回 `Connection: keep-alive` + `Transfer-Encoding: chunked`，body 没读完连接就不归还 Chrome 每域名 6 条连接池。滚动进度上报（`use-read-progress.ts` 的 PATCH）每次查词/滚动都发，攒够 6 条后所有请求 Stalled；GC/超时释放后恢复 —— 完全对应用户描述的循环。

**复现脚本证据**：在页面里每轮发 6 个不读 body 的 PATCH，随后查词：第 1、2 轮 115/111ms；第 3 轮起 5 秒超时（AbortError），之后持续卡。纯查词压测 81 次点击 0 慢请求 0 pending，排除词典链路。

**修复**：
- 所有不读 body 的 fetch 加 `.then(res => res.arrayBuffer())`：`use-read-progress.ts`（进度上报 ×2）、`ProfileMenu.tsx`、`SurveyPrompt.tsx`、`LearnerPanel.tsx`（reset + 开关）、`TextManageDialog.tsx`、`WordList.tsx`（star/delete）。
- AI 流取消链路：`triggerAI` 先 abort 上一条；分段小结加 `summaryAbortRef` + signal；`streamExplain`/`streamTurns`/`streamSectionSummary` 支持 `signal`，`openaiStream` 把 signal 作为 SDK RequestOptions 第二参数传入；`explain-handler`/`summarize` 的 `cancel()` 调用 `abort.abort()`；`isRetryableError` 把 abort 列为不可重试。
- 建卡进度 UI：`MakeCardButton.tsx` 用 conic-gradient 圆环（`--rf-pct` + `@property` 平滑过渡）+ 百分比 + "预计还需约 N 秒 · 估算"。服务端只有 generating 状态，所以是标注为估算的曲线（最高 95%），不冒充精确进度。`globals.css` 加 `.rf-progress-ring` / `.rf-card-progress-note`。
