# 长文性能实测（P5）

> 2026-11-03 · Next 16.4.3 生产构建 · Playwright + 系统 Chrome 无头 · M1 Pro (macOS 15.8.1)
> 结论先行：**不做虚拟滚动。** 4 万词以内真实瓶颈是 SSR HTML 体积与水合，不是渲染交互；实测规模远低于劣化点。

## 测法

- 用 [scripts/bench-reader.mjs](../scripts/bench-reader.mjs) 往库里塞 `[bench]` 文本 → 无头 Chrome 打开阅读页 → 量完删掉，不污染正式数据。
- 样本：Lilian Weng《Prompt Engineering》（3,967 词 / 149 段）真实文章，另把它重复 ×4、×10 造 15,868 / 39,670 词的压力样本（段落分布不变，只放大规模，控制变量）。
- `CPU=4` 用 CDP `Emulation.setCPUThrottlingRate` 模拟中端手机的主线程。
- 每个场景跑多轮取中位数。指标：
  - **TTFI**：导航开始 → 首次点击词能弹出释义层（load 事件 + 水合探测）。
  - **clickPaint**：点词 → 弹层可见的下一帧（MutationObserver 测 DOM 插入 + 双 rAF 测绘制）。
  - **TBT**：全程 long task 超出 50ms 部分之和。

## 结果

| 文本规模 | DOM 元素 | HTML 体积 | JS 堆 | TTFI @1x | TTFI @4x | 点词→弹层 | 收词 | 滚动 p95 | TBT @1x / @4x |
|---|---|---|---|---|---|---|---|---|---|
| 91 词（基线） | 259 | 19 KB | 4 MB | ~620 ms | 622 ms | 18 ms | 19 ms | 19 ms | 19 / — ms |
| 3,967 词（真实博客） | 8,200 | 320 KB | 7 MB | ~530 ms | 760 ms | 17 ms | 19–34 ms | 18 ms | 0 / 74 ms |
| 15,868 词（×4） | 32,581 | 1.25 MB | 17 MB | ~640 ms | — | 17 ms | 18 ms | 18 ms | 0 / 170 ms |
| 39,670 词（×10） | 81,343 | 3.1 MB | 33 MB | ~900 ms | 2,466 ms | 17 / 51 ms | 34 / 41 ms | 18 ms | 21 / 627 ms |

（点词→弹层一栏，39,670 词给的是 1x / 4x 两个值；TTFI 为多轮中位数的近似值。）

## 结论

1. **1.5 万词以内全绿**：TTFI 与 91 词的短文几乎没差别（JS 框架本身的启动占大头），所有交互都在一帧预算内。真实博客（4 千词）在任何设备档位都毫无压力。
2. **4 万词是"弱设备才会疼"的量级**：桌面级 CPU 依旧流畅（TTFI < 1s、点击一帧内、滚动满帧）；4 倍降速后 TTFI 2.5s、TBT 600ms+、点词 50ms，开始可感知但没到不可用。
3. **瓶颈在载荷不在渲染**：3.1MB 的 SSR HTML（每个词一个带 data 属性的 span，体积是纯文本的 ~120 倍）+ 水合 8 万节点。交互路径（点词、收词、滚动）反而不随规模明显变差——`Para` 有 `memo`，点击只重渲染弹层。
4. **收词的全量 reconcile 实测便宜**：收词会让 `savedSet` 换引用 → 所有段落重新 reconcile，但 4 万词也只要 34–41ms，在预算内，不值得为它引入命令式 DOM 操作。

## 决定

- **P5 不引入虚拟滚动**：虚拟滚动会破坏浏览器原生 Ctrl+F 和跨段文本选择（阅读器的核心交互），而实测在真实文章量级（≤1 万词）没有任何收益。不值得。
- **软上限**：导入超过 ~2 万词（约 50 屏）时，UI 提示"长文，弱设备首屏可能偏慢"。目前未实现，列为待办。
- **如果将来真要优化**，方向是**分段懒渲染**（首屏只挂载前 N 段，IntersectionObserver 增量补齐），比虚拟滚动便宜一个数量级，且不破坏文本选择和搜索。触发条件：单文本常态超过 2 万词，或出现移动端阅读需求。

## 复跑

```bash
npm run build && npm start
SAMPLE=/path/to/article.txt npm run bench        # 造样本 + 测量 + 清理
BASE=http://127.0.0.1:3000 CPU=4 ROUNDS=3 npm run bench
```

环境变量见脚本头部注释。`COLLECT=1` 会额外测收词开销，但会真的往词库写一个词，默认关闭。
