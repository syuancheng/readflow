# ReadFlow 设计规范 v1（草案）

> token 定义：[`src/styles/tokens.css`](../src/styles/tokens.css)　·　可视化预览：[`docs/design-system.html`](design-system.html)
>
> 一句话：**多邻国的「实体按钮 + 鲜绿主操作」，配克制的灰阶、细线和留白。** 颜色负责表达含义，不负责装饰。

## 0. 为什么要有这份规范（现状盘点，2026-11-11）

| 维度 | 现在实际出现的取值数 | 规范后 |
|---|---|---|
| 字号 | 26 种（含 11.5 / 12.5 / 13.5 / 14.5 / 16.5px 这类半像素） | 7 档 + 阅读器 1 档 |
| 字重 | 6 种（400–900） | 4 档 |
| 间距 | 30+ 种（3 / 5 / 7 / 9 / 11 / 13 / 22 / 26 / 58 / 76px…） | 10 档，全是 4 的倍数 |
| 圆角 | 25 种（3–22px） | 4 档 + 全圆 |
| 阴影 | 约 20 种 | 3 档 + 按钮实体底边 |
| 颜色 | 3 套并存的色板（`--duo-*` 多邻国、`--wb-*` 蓝灰工作台、`--rf-*` 半套），外加 50+ 个散落的 hex | 1 套 |
| 页面最大宽度 | 4 种（`max-w-3xl` / `6xl` / `1440px` / 不限） | 1 种 |

## 1. 颜色

### 1.1 每种颜色只有一个含义

| 颜色 | 语义 token | 只能用于 | 不能用于 |
|---|---|---|---|
| 绿 | `--rf-accent*` | 主操作按钮（一屏最多一个）、进度条、品牌 Logo、成功状态 | 选中态、普通文字、释义、标题装饰 |
| 浅绿 | `--rf-highlight-*` | 阅读器和词库原句里「查过的词」的高亮 | 其它任何底色 |
| 蓝 | `--rf-info*` | 链接、信息提示、输入框聚焦环 | 选中态、tab |
| 紫 | `--rf-ai*` | 一切 AI 产出：问 AI、AI 释义、分段小结 | 非 AI 功能 |
| 橙 | `--rf-reward*` | 游戏化：XP、连续天数、成就 | 警告（警告用红或文字） |
| 红 | `--rf-danger*` | 删除、错误、作废 | 难度、强调 |
| 灰 | `--rf-text-*` / `--rf-bg-*` / `--rf-border*` | 其余所有东西 | — |

CEFR 难度徽章是唯一例外的「专用色」：A 级绿、B 级蓝、C 级紫（`--rf-level-*`），只出现在难度徽章上。

### 1.2 文字只有三种颜色

- `--rf-text-primary` `#3c3c3c`：正文、标题、选中项。
- `--rf-text-secondary` `#6b6b6b`：说明、日期、计数、未选中导航（白底对比度 5.3:1）。
- `--rf-text-disabled` `#afafaf`：**只用于禁用态**。可读的信息不能用它（对比度 2.2:1，看不清）。

彩色文字只能用各色的 `-text`（700 档）变体，例如 `--rf-accent-text #3f7f00`。**`#58cc02` 永远不能当文字色**：它在白底上的对比度只有 2.1:1。

### 1.3 「选中」只有一种长相

| 场景 | 样式 |
|---|---|
| 顶部导航当前页 | 文字 `primary` + 加粗 + 底部 3px 绿色指示条；**不加底色、不加边框** |
| 侧栏 / 筛选 chip / 列表的选中项 | 底色 `--rf-bg-selected` + 文字 `primary` + 字重 600 |
| 分段控件（全部 / 单词 / 短语，粘贴 / 上传 / 网页） | 轨道 `--rf-bg-subtle`，选中段为白底 + `--rf-shadow-sm` |
| 复选框、开关 | 绿色填充（这是「勾上了」，不是「当前位置」） |

## 2. 字体

| 用途 | token | 字族 |
|---|---|---|
| 所有界面文字和阅读正文 | `--rf-font-sans` | DM Sans；中文回退到 PingFang SC / 微软雅黑 |
| 音标 | `--rf-font-ipa` | 系统字体（SF / Segoe），因为它们带 IPA 字形 |
| 代码 | `--rf-font-mono` | Geist Mono |

- 取消导航专用的 Outfit 字体。一个产品只用一套西文字族。
- **音标看起来像乱码的原因**：词典数据本身是对的。`concept` 的音标存的是 `ˈkɒnsept`，`ɒ` 的编码是 U+0252。问题在于阅读器用 `font-mono`（Geist Mono）以 13px 显示音标：等宽字体里的 `ɒ` 很像 D，`ˈ` 很像直引号。音标是给人辨音的，不该用代码字体，改用 `--rf-font-ipa`，字号至少 `sm`。

### 2.1 字号阶梯

| token | 字号 / 行高 | 用途 |
|---|---|---|
| `xs` | 12 / 16 | 徽章、计数、角标 |
| `sm` | 14 / 20 | 次要信息、元数据、表单说明、小按钮 |
| `md` | 16 / 24 | **默认**：正文、按钮、输入框、列表行 |
| `lg` | 18 / 28 | 卡片标题、词条释义标题、文章标题 |
| `xl` | 20 / 28 | 区块标题（「我的文本」「导入文本」） |
| `2xl` | 24 / 32 | 页面标题、弹窗标题、词条大字 |
| `3xl` | 32 / 40 | 首页 Hero、战绩大数字 |
| `reading` | 19 / 36 | 阅读器正文（用户可调） |

规则：

- 一个组件内最多出现 **3 个字号**。
- 相邻两级标题至少隔一档，比如区块标题用 `xl` 时，卡片标题用 `md` 加粗，而不是 `lg`。
- 禁止半像素字号，禁止用 `em` 做字号缩放（阅读器正文里的块级元素除外）。

### 2.2 字重

400 正文 · 600 标签、导航、强调 · 700 标题、按钮 · 800 只给 Hero 和大数字。禁止 500 和 900。

## 3. 间距（4px 基准）

`4 · 8 · 12 · 16 · 20 · 24 · 32 · 40 · 48 · 64`，对应 `--rf-space-1` 到 `--rf-space-16`。

| 关系 | 用多少 |
|---|---|
| 图标与文字、徽章之间 | 4–8 |
| 同一组内的元素（标签与输入框、按钮组） | 8–12 |
| 卡片内边距 | 16（紧凑）/ 24（默认） |
| 列表项之间 | 0（用分隔线）或 8 |
| 区块之间（卡片与卡片、区块标题与内容以外） | 24–32 |
| 页面顶部到第一个区块 | 32 |
| 页面左右留白 | 24；手机 16 |

**亲密性原则**：组内间距必须小于组间间距。例如区块标题和它的内容之间是 12–16，两个区块之间是 32。

## 4. 圆角

| token | 值 | 用于 |
|---|---|---|
| `sm` | 8 | 徽章、标签、小图标按钮 |
| `md` | 12 | 按钮、输入框、下拉框、可点击的列表行 |
| `lg` | 16 | 卡片、面板 |
| `xl` | 24 | 弹窗、抽屉 |
| `full` | 999 | 头像、圆形按钮、进度条、计数药丸 |

**嵌套规则**：内层圆角 = 外层圆角 − 内边距（最小取 `sm`）。例如 16 圆角的卡片如果内边距是 8，里面的元素用 8。

## 5. 边框与阴影

- **边框**：一律 1px `--rf-border`；输入框和次要按钮用 `--rf-border-strong`。
- **实体底边**：主按钮和次要按钮保留多邻国的 4px 底边，按下时变成 2px 并下沉 2px。**这是全站唯一的粗边。**
- **阴影只有三档**：
  - `sm`：卡片悬停、吸顶栏。
  - `md`：下拉菜单、气泡、Toast。
  - `lg`：弹窗、抽屉。
- **静止的卡片不加阴影**：靠 1px 边框和留白分层。
- **不嵌套框**：卡片里面不再放带边框的灰底容器。需要分组时，用间距或者一条分隔线。

## 6. 布局

- 除阅读器外，所有页面的最大宽度都是 `--rf-container`（1200px），居中。左右留白用 `--rf-gutter`。**内容区的左边缘要和顶部导航的 Logo 对齐。**
- 页面结构固定为：顶部导航 → 32 → 页面头（可选：一行 `2xl` 标题，加一行 `sm` 说明）→ 24 → 内容。
- 双栏页面（首页、词库）：主栏自适应，侧栏 240px（词库）或 360px（首页导入），栏间距 32。
- 断点：640（手机）· 860（侧栏折叠）· 1024（平板）。

## 7. 图标

- 功能图标统一用一套线性图标，计划用 lucide-react。尺寸 16（行内）或 20（按钮），线宽 2，颜色跟随文字色。
- emoji 只出现在游戏化位置（⚡ XP、🔥 连续天数、🏅 成就）和空状态插画里，不当作功能图标。

## 8. 组件对照（迁移清单）

| 组件 | 规范 |
|---|---|
| 主按钮 | `md` 字号、700、高 44、左右内边距 20、圆角 `md`、绿底白字、4px `accent-edge` 底边 |
| 次要按钮 | 白底、`primary` 文字、1px `border-strong` 外加 4px 同色底边 |
| 小按钮 | 高 32、`sm` 字号、左右内边距 12 |
| 输入框 | 高 44、`md` 字号、圆角 `md`、聚焦时 `--rf-focus-ring` |
| 徽章 / 标签 | 高 24、`xs` 字号、600、圆角 `sm`、左右内边距 8；默认灰底，只有难度、AI、已导出这几种用彩色 |
| 卡片 | 白底、1px 边框、圆角 `lg`、内边距 24（紧凑时 16） |
| 列表行 | 高至少 56、上下内边距 12、行间 1px 分隔线、悬停 `bg-hover` |

## 9. 怎么保证严格遵守

`scripts/check-tokens.mjs` 已挂进 `npm test`（也可以单独跑 `npm run check:tokens`）。它扫描 `src/**/*.css`（tokens.css 除外）和 `src/**/*.tsx`，出现以下任何一项就报错：

- **CSS**
  - 裸 hex 颜色。`globals.css` 开头的旧变量别名表例外。
  - `font-size` 不是 `var(--rf-text-*)`。阅读器正文里按比例缩放的 `em` 例外。
  - 字重不在 400 / 600 / 700 / 800 之内。
  - padding、margin、gap 的 px 值不在阶梯里。阶梯是 0 · 4 · 8 · 12 · 16 · 20 · 24 · 32 · 40 · 48 · 64，另外允许 1px 和 2px 的微调。
  - 圆角不是 token、`0` 或 `50%`。
  - 阴影不是 token、`none`、inset 指示条或白色描边环。
- **TSX**
  - 使用 `text-[13px]` 这类任意值字号。
  - 使用 `mb-1.5` 这类半步间距，或阶梯以外的 `[Npx]` 间距。
  - 使用 `font-medium` 或 `font-black`。
  - style 里写死字号数字或 hex 颜色。

补充约定：

- 间距可以直接写阶梯里的 px 数值，不强制写成 `var(--rf-space-*)`。
- 组件可以直接引用基础色板，例如 `--rf-gray-200`，但优先用语义 token。
- 旧变量名 `--duo-*` 和 `--wb-*` 现在只是语义 token 的别名，新代码不要再用。
- 确实需要例外时，在那一行写注释 `token-ok: 原因`。代码评审时检查这些注释。
- 圆角另加了一档 `xs`（4px），只给行内高亮和复选框这种极小元素用。

Tailwind 主题已经对齐 token：`text-xs` … `text-3xl`、`rounded-xs` … `rounded-xl`、`shadow-sm/md/lg` 的取值都来自 tokens.css，可以直接用。
