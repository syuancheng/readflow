# P58 多条「回复」：选中 AI 回答 → 写批注 → 加进输入框（设计与实现规格）

> 状态：待评审（只有计划，没有代码改动）　日期：2026-11-20
> 参照：Claude Code 的 Reply 流程。前置：P44（右栏聊天）、本周的「引用左竖线」两次调整。

## 0. 结论

把现在"选中 → 点一下把整段放进输入框（只能一条）"改成 Claude Code 的 Reply 流程：

1. 在 AI 回答里选中一段文字，浮出一个「回复」；
2. 点开后**就在选区旁边有一个单行输入**，写下针对这一段想说什么（可不写），回车；
3. 这一条"引用 + 批注"被**加进底部输入框**，成为输入框里的一个条目；
4. 可以对不同段落**连续这样做，最多 5 条**，每条可单独删除；
5. 底部输入框的话可以不写：**有引用条目就能直接发送**；
6. 发送后气泡里按顺序显示每条"引用 + 批注"，再是最后那句话；模型收到全部条目。

## 1. 已拍板

| 问题 | 决定 |
|---|---|
| 批注是否必填 | 不必填；只引用不写批注也可以加入 |
| 数量与长度上限 | 最多 5 条；每条引用 ≤ 500 字（沿用现有 `EXPLAIN_QUOTE_MAX_CHARS`）；每条批注 ≤ 200 字 |
| 只有引用、底部没写字能否发送 | 能。此时问题标签记为「针对引用的回复」，发给模型的问题写成"学生没有另外提问，请针对他引用的几处话和批注回答" |

## 2. 现状（附出处）

- 单条引用：`Reader.tsx:1599` 的 `askQuote: { text; turnIndex } | null`；`ChatTurn.tsx` 在选区 mouseup 时弹 `SelectionAskBar`，点按钮调 `onQuote(text)` → `setAskQuote`（`Reader.tsx:2053`），再选就覆盖。
- 输入框：`AskComposer.tsx` 的 `quote` / `onClearQuote` 是单个；`send()` 要求底部文字非空。
- 请求：`Reader.tsx:1799` 把 `quote` 随请求发出，发完 `setAskQuote(null)`；服务端 `narrowQuote`（`ai.ts:499`）只收一条；`buildUserMessage` 把它写进"你引用了自己上一条回答里的这段话"。
- 对话串存储（`ai-thread.ts`）：每轮可有一行 `【引用】…` 紧跟在 `【追问】` 之前，`ThreadTurn.quote?: string`；解析时 `pendingQuote` 只存一条。
- 历史（`history`）只带 `{ask, text}`，**不带引用**；做卡只读 `ask`/`text`，不受影响。

## 3. 数据模型

```ts
type Reply = { text: string; note?: string }      // 一条回复：引用的原话 + 我的批注
// ThreadTurn.quote?: string   → 保留（读旧数据用），新增：
// ThreadTurn.replies?: Reply[]
```

- **读旧数据**：解析 `【引用】…`（无批注）时，同时得到 `replies = [{ text }]`；旧 `quote` 字段仍填（= 第一条的 text），所有旧调用方不受影响。
- **写新数据**：多条回复写成按顺序的多组行，紧跟在 `【追问】` 之前：
  ```
  【引用】第一段原话
  【批注】我对第一段的话
  【引用】第二段原话
  【追问】底部那句话
  回答…
  ```
  - `【批注】` 一定紧跟在对应的 `【引用】` 之后，没有批注就省略。
  - 引用和批注压成一行存（沿用 `oneLine`）；批注中的换行换成空格。
  - 只有一条引用且无批注时，输出与现在**逐字相同**（旧版本读取不受影响）。
- **解析容错**：连续多个 `【引用】` 各自成组；孤立的 `【批注】`（前面没有引用）丢弃；超过 5 组只取前 5 组。

## 4. 请求与提示词

- 请求体新增 `replies: Reply[]`；旧的 `quote: { text, turnIndex }` 继续被接受（单条，等价于 `replies=[{text}]`），两者同时出现时以 `replies` 为准。
- `narrowReplies(v)`（放在 `ai.ts`，与 `narrowQuote` 同款白名单）：只取 `text`（≤500）、`note`（≤200），最多 5 条，空文本整条丢弃，额外字段不透传。
- `ExplainParams.replies?: Reply[]`。
- 提示词（`buildUserMessage`，v1；`buildUserTail`，v2）把引用段改为：
  - **只有 1 条且无批注**：与现在逐字相同——「你引用了自己上一条回答里的这段话：\n「…」」（保证 v1 快照与旧行为不变）。
  - **其他情况**：
    ```
    你引用了自己前面回答里的几处话，并写了批注（按顺序）：
    1. 「引用原话」
       学生的批注：……
    2. 「引用原话」
    ```
    没有批注的条目不写"学生的批注"行。
  - 没有底部问题时，"学生的问题"那一行写：`学生没有另外提问，请针对他引用的几处话和批注回答。`
- v2 分层：引用只在 L5 尾部，不影响前缀缓存。

## 5. UI

### 5.1 选区浮层（`SelectionAskBar.tsx`）
- 现在：一个「添加到对话」按钮。
- 改为：先是一个「回复」按钮（同样的白底、细边框、图标）；**点击后原地展开成一个单行输入**（宽约 280px，贴选区起点，窗口放不下就换到选区上/下方，不超出视口），占位文字「对这段话说点什么（可不写）」。
  - 回车（非输入法组字中）→ 加入；Esc → 收起并取消；点浮层外 → 关闭（与现在一致）。
  - 空回车 = 只加引用、不写批注。
  - 已有 5 条时，按钮禁用并提示「最多 5 条」。
  - 选区文字在点击前已被保存（现有逻辑），展开输入框导致原生选区消失不影响。

### 5.2 输入框里的回复列表（`AskComposer.tsx`）
- `quote` / `onClearQuote` → `replies: Reply[]` / `onRemoveReply(index)`。
- 每条是输入框内的一行（延续上一版的竖线 + 灰字语言）：
  - 第一行：3px 左竖线 + 引用文字（单行省略）+ ×；
  - 有批注时，第二行：批注（主文字色、sm、单行省略），缩进与引用文字对齐。
- 区域最大高度约 112px（约 4 条），超出内部滚动；整个输入框多行时"＋"和发送仍在最下面一行。
- `send()`：底部文字或回复列表任一非空即可发送；两者都空不发送。发送后清空两者。
- 无回复时，输入框与现在完全一样。

### 5.3 对话气泡（`ChatTurn.tsx` + `p44-chat.css`）
- 用户气泡里按顺序显示每条回复：竖线引用块（沿用 `.rf-bubble-quote`）+ 下面一行批注（正常字色，无竖线）；再是底部那句话。
- 只有引用没有底部文字时，气泡里不再单独显示「针对引用的回复」这个标签，只显示回复；该标签仅作为对话串里的问题标题存储和"复制/修改"用。
- 旧对话（只有 `quote`）渲染为一条无批注的回复，样子与现在的左竖线引用一致。

### 5.4 失败轮次的操作
- 「重试」沿用 `req`，需要把 `replies` 存进 `req`，重试时一并重发；「修改」把回复条目放回输入框（若超过 5 条则取前 5 条）。

## 7. 测试

### 7.1 单测
| 用例 | 断言 |
|---|---|
| `ai-thread` 往返 | 多条回复（含/不含批注）序列化再解析得到同样的 `replies`；单条无批注时输出与旧格式逐字相同；旧格式（单个 `【引用】`）解析出 `replies=[{text}]` 且 `quote` 保持；孤立 `【批注】` 丢弃；超过 5 组截断 |
| `narrowReplies` | 白名单、长度裁剪（500/200）、最多 5 条、空文本丢弃、非法结构丢弃；旧 `quote` 被兼容 |
| `buildUserMessage` / `buildUserTail` | 1 条无批注与改前**逐字相同**；多条带批注的格式；没有底部问题时的问题行；v2 下前缀不变量仍成立（引用只改尾部） |

### 7.2 e2e（`scripts/e2e-chat-panel.mjs`，沿用现有的选区/引用用例）
- 选中 → 点「回复」→ 展开输入框 → 写批注回车 → 输入框里出现一行回复（含批注行）；
- 再选另一段 → 再加一条 → 输入框里有两条；点其中一条的 × 只删那一条；
- 加满 5 条后「回复」按钮禁用；
- 底部不写字直接发送：请求体里 `replies` 有内容、没有底部文字也成功；气泡里按顺序显示每条引用 + 批注；
- 请求体检查：`replies` 的条数、文字、批注与界面一致；
- 重试一个失败轮次，`replies` 保留；
- 窄宽度（768）下浮层输入不超出视口；`C1/C2/C3` 等输入框用例仍通过。

## 8. 风险与取舍

| 风险 | 缓解 |
|---|---|
| 浮层里的输入框在窄右栏放不下 | 固定最大宽度 280px，贴近选区且用视口边界约束；放不下时换到选区另一侧 |
| 输入法组字时回车误提交 | 沿用现有的 `isComposing` 判断 |
| 对话串格式变化影响旧数据 | 单条无批注时输出逐字不变；解析兼容旧格式；单测覆盖 |
| 多条引用把请求撑大 | 5 条 × 500 字上限；只放在尾部，不进缓存前缀 |
| 引用文字过长挤占输入框 | 每条单行省略 + 区域最大高度约 112px 内滚动 |

## 9. 不做

- 不让引用可跨多条回答合并成一条；不支持编辑已加入的条目（要改就删掉重加）；不做引用块点击跳转到被引用的回答（可作为后续）。
- 不改变历史压缩和做卡对引用的处理（历史本来就不带引用）。
