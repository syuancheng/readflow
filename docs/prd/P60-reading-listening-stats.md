## 1. 背景与问题

当前 `/stats`（战绩页）的核心统计完全围绕**「收集生词数（`contexts`）」**和**「书架文章总数（`texts`）」**构建，存在三个核心体验问题：

1. **指标与真实语言进步脱钩**：阅读能力提升最直接的度量是**「真正读懂的英文总词数」**（类似跑步看公里数、减脂看热量缺口）。用「每天收了多少生词」做主指标会产生反向激励——用户越熟练、生词越少，战绩图表反而越难看。
2. **囤货被计入战绩**：现有 `textCount` 与 `totalWords` 统计的是导入书架的全部文本，未区分是否真正读完，而库中已有的 `texts.completedAt`（用户显式点击「标记已读完」才写入的时间戳）尚未用于统计。
3. **缺少听力维度**：用户当前同时推进阅读与听力（如托福备考、英文音频精听），但站内暂未上线 MP3 上传与精听功能（见 `P59-listening.md`），缺少一个统一的地方记录和回看每日及累计的听力有效投入。

---

## 2. 目标与非目标

### 目标
1. **阅读战绩以「完全读懂的词数」为核心**：用户读完一篇英文文章（无论通过查词、AI 讲解还是精读，最终确认完全看懂）并点击「标记已读完」后，该文章的 `wordCount` 计入**今日读懂词数**与**账号创建以来的累计读懂词数**。
2. **新增「听力」统计与极简手动录入**：在 `/stats` 中增加听力战绩模块，支持展示**今日听懂时长**、**累计听懂时长**及近期趋势，并提供极简的手动录入与记录管理能力。
3. **面向 P59 的平滑演进**：听力数据模型预留来源标识与文章关联字段，待 P59 站内听力功能上线后可直接自动入账，无需重构战绩页或迁移历史数据。
4. **前端 UI 保持高级、克制、清晰**：严格遵循 ReadFlow 现有设计系统（中性控件 + 数据绿图表 + 清晰留白与对齐），提供类似运动手表的客观反馈感，不做花哨游戏化或鸡汤弹窗。

### 非目标（本期不做）
- 不做音频上传、播放器或句子对齐（属 P59 范围）；
- 不做按段落增量拆分的多日长文词数统计（本期以文章级「标记已读完」为最小结算单元，保持 0 阅读器侵入）；
- 不做外部快捷指令 / Webhook API 对接（可在 P60 稳定后作为后续小迭代扩展）。

## 3. 核心指标定义与业务规则

### 3.1 阅读指标（基于现有 `texts` 表，零改表）

| 指标 | 定义与计算口径 | 说明 |
|---|---|---|
| **今日读懂词数** | 当天（本地时区 `YYYY-MM-DD`）`completedAt` 落入今日的已完读文章 `sum(wordCount)` | 排除 `sourceType = 'web'` 的网页插件单句摘录 |
| **累计读懂词数** | 账号创建以来所有 `completedAt IS NOT NULL` 且 `sourceType != 'web'` 的 `sum(wordCount)` | 核心总里程（如 `12,500 词`） |
| **本周 / 本月读懂词数** | 本周一至今 / 本月 1 日至今已完读文章 `sum(wordCount)` | 辅助呈现近期推进节奏 |
| **已读完篇数** | `completedAt IS NOT NULL` 且 `sourceType != 'web'` 的文章总数 | 替代原有的「书架总篇数」 |
| **连续阅读天数 / 最长连续** | 复用 `lib/streak.ts` 的 `computeStreaks`，输入源从「收词日期」改为「有完读词数的日期」 | 当天未完读不算断档，逻辑与现有一致 |
| **每日趋势（14 天柱状图 & 18 周热力图）** | 按 `date(completedAt / 1000, 'unixepoch', 'localtime')` 聚合 `sum(wordCount)` | 鼠标悬停 tooltip 显示 `YYYY-MM-DD · 1,250 词` |

**边界规则**：
- **取消完读实时扣减**：若用户在阅读页再次点击「✓ 已读完」取消标记（`completedAt` 置为 `null`），对应词数自动从当日与累计统计中扣除。
- **重读/改期**：仅记录最后一次点击「标记已读完」的时间戳（复用 P18 既有行为）。
- **收集生词降级为次要信息**：不再占据顶部四连卡首屏位置，保留「最近收下的词」轻量模块或折叠至页尾，避免干扰核心里程指标。

### 3.2 听力指标（新增 `listening_logs` 表，支持手动录入）

| 指标 | 定义与计算口径 | 说明 |
|---|---|---|
| **核心单位** | **彻底听懂的音频净时长（分钟）** | 累计超过 60 分钟时，大数字支持友好展示（如 `12.5 小时` 或 `750 分钟`，悬停/副标显示精确分钟） |
| **今日听懂时长** | `log_date = 今日` 的 `sum(minutes)` | 精确到 `0.5` 分钟（如 `1.5 分钟`、`15 分钟`） |
| **累计听懂时长** | 账号创建以来全部记录的 `sum(minutes)` | 核心总里程 |
| **本周 / 本月听懂时长** | 本周一至今 / 本月 1 日至今 `sum(minutes)` | 对标跑步周跑量 / 月跑量 |
| **连续听力天数** | 复用 `computeStreaks`，按有记录的 `log_date` 计算 | 今天未记不算断档 |
| **每日趋势（14 天柱状图 & 18 周热力图）** | 按 `log_date` 聚合 `sum(minutes)` | 视觉组件与阅读完全同源复用 |

## 4. 功能需求明细

### F1：战绩页顶部「阅读 / 听力」切换与总览
- 在 `/stats` 页面顶部提供清晰的分段控件（Segmented Control）：**「阅读」**（默认）｜**「听力」**，样式严格复用 `docs/design-system.md §1.3` 分段控件规范（`--rf-bg-subtle` 轨道 + 白底 `--rf-shadow-sm` 选中段）。
- 切换 Tab 仅切换下方数据视图（可用 URL 参数 `?tab=listening` 保持刷新不丢失），保证单屏信息聚焦、停顿点 ≤ 5。

### F2：阅读战绩视图
1. **核心四连卡**（桌面 4 列，手机 2×2）：
   - **累计读懂词数**（主焦点大数字，如 `24,800` + 单位 `词`）
   - **今日读懂词数**（如 `500 词`，副标显示本月累计如 `本月 6,200 词`）
   - **已读完篇数**（如 `18 篇`）
   - **连续阅读天数**（如 `5 天`，副标显示 `最长 12 天`）
2. **学习日历（18 周热力图）+ 最近 14 天柱状图**：
   - 沿用现有 `lg:grid-cols-[auto_minmax(0,1fr)]` 桌面并排布局；
   - 柱状图顶部数字显示当日词数（超过 1,000 时紧凑显示如 `1.2k`），今日柱子用 `--rf-data` 突出；
   - 热力图色阶按词数分档（`0` / `<500` / `500–1499` / `1500–2999` / `≥3000`）。
3. **最近读完的文章列表**（替代原「书架」全量列表）：
   - 仅展示已完读（`completedAt IS NOT NULL`）的文章，按完读时间倒序，最多显示最近 10 篇；
   - 每行展示：文章标题（点击跳转阅读页）、CEFR 难度标签（复用 `CefrBadge`）、完读日期、词数（如 `520 词`）。
4. **空状态引导**：当累计读懂词数为 `0` 时，文案温和引导：「读完一篇文章后，点击阅读页右上角的『标记已读完』，它的词数就会计入这里。」

### F3：听力战绩视图与手动录入
1. **核心四连卡**（与阅读视图完全对称的视觉结构）：
   - **累计听懂时长**（如 `8.5 小时` 或 `510 分钟`）
   - **今日听懂时长**（如 `15 分钟`，副标显示 `本月 120 分钟`）
   - **累计记录次数**（如 `24 次`）
   - **连续听力天数**（如 `4 天`，副标显示 `最长 9 天`）
2. **极简手动录入区（核心交互，追求 10 秒完成）**：
   - 在听力视图顶部四连卡下方（或右侧栏）提供轻量录入表单，**不弹窗、展开即用**（或点击「+ 记录听力」平滑展开，建议默认单行紧凑内联表单，降低点击阻力）：
     - **听懂时长（必填）**：数字输入框，单位「分钟」，支持 `0.5` 步进（范围 `0.5` ~ `600`），下方提供 4 个快捷填充 chip（`5 分钟` / `15 分钟` / `30 分钟` / `60 分钟`），点一下直接填入；
     - **练习类型（选填，默认精听）**：`精听`（听懂 100%）｜`泛听`（听懂大意）；
     - **日期（选填，默认今天）**：日期选择器，支持补录前几天的数据；
     - **备注（选填）**：单行文本，placeholder 如「材料名或主题，如新托福短对话 #12」；
     - **提交按钮**：全屏唯一主按钮（`--rf-accent` 墨绿底白字），提交后无刷新更新四连卡、热力图、柱状图与记录列表。
   - **口径提示（一行小字）**：在表单旁用 `--rf-text-secondary`（12px/14px）温和提示：「建议只记关掉字幕真正听懂的音频净时长；未来站内支持上传音频后将自动累计。」
3. **听力日历（18 周热力图）+ 最近 14 天柱状图**：
   - 与阅读视图共用完全一致的组件与布局，单位为分钟；
   - 热力图色阶按分钟分档（`0` / `<10` / `10–29` / `30–59` / `≥60`）。
4. **最近听力记录列表（支持删除修正）**：
   - 按日期与创建时间倒序展示最近 20 条记录；
   - 每行展示：日期、类型标签（`精听` / `泛听`，遵循标签规范）、备注（无备注显示「听力练习」）、时长（如 `+15 分钟`）、来源标识（仅当未来 `source = 'audio'` 时显示「自动」标签，手动不额外加噪音）；
   - 每行右侧提供 hover 显现的删除图标按钮（带轻量二次确认或撤销提示），方便修正误录。

## 5. 数据模型与接口设计

### 5.1 数据库变更

**阅读模块**：复用现有 `texts` 表（`word_count`、`completed_at`、`source_type`、`user_id`），建议新增联合索引加速查询：
```sql
CREATE INDEX IF NOT EXISTS idx_texts_user_completed ON texts(user_id, completed_at);
```

**听力模块**：新增 `listening_logs` 表（在 `src/db/schema.ts` 定义，并在对应的 `ensure` 初始化脚本中建表，遵循项目既有约定）：

```sql
CREATE TABLE IF NOT EXISTS listening_logs (
  id          TEXT PRIMARY KEY,
  user_id     TEXT NOT NULL,
  log_date    TEXT NOT NULL,           -- 本地日期 YYYY-MM-DD，方便按天聚合与补录
  minutes     REAL NOT NULL,           -- 彻底听懂的净时长（分钟），支持 0.5 步进
  mode        TEXT NOT NULL DEFAULT 'intensive', -- 'intensive'(精听) | 'extensive'(泛听)
  note        TEXT,                    -- 选填备注（材料名/主题，最长 200 字）
  source      TEXT NOT NULL DEFAULT 'manual',    -- 'manual'(手动) | 'audio'(预留给 P59 自动入账)
  text_id     TEXT,                    -- 预留外键：未来 P59 关联具体文章 ID，可空
  created_at  INTEGER NOT NULL
);

CREATE INDEX IF NOT EXISTS idx_listening_logs_user_date
  ON listening_logs(user_id, log_date);
```

### 5.2 API 接口设计

均需通过 `currentUser()` 鉴权，严格按 `user.id` 隔离数据（不可越权读写他人记录）：

1. **`GET /api/stats?tab=reading|listening`**（或在 Server Component 中直接调用 `getReadingStats` / `getListeningStats`，客户端录入听力后调用接口刷新）：
   - 返回当前用户的统计汇总、14 天柱状图数据、18 周热力图数据及最近记录列表。
2. **`POST /api/listening-logs`**
   - Body：`{ minutes: number, logDate?: string, mode?: "intensive" | "extensive", note?: string }`
   - 校验：`minutes` 必须为有限正数且 `0.5 <= minutes <= 600`；`logDate` 若传需符合 `YYYY-MM-DD` 且不晚于今日；`note` 裁剪至 200 字符以内。
   - 返回：`201 Created` + 新建记录与更新后的听力统计摘要。
3. **`DELETE /api/listening-logs/[id]`**
   - 校验记录归属 `userId === user.id`，物理删除该记录并返回 `200 OK`。

## 6. 前端 UI 与视觉设计规范（强制执行）

本功能的前端实现必须严格遵守 `docs/design-system.md` 与 `DESIGN.md` 中的四原则，并满足以下具体要求：

### 6.1 色彩与视觉层级
- **中性控件 + 数据绿图表**：
  - 所有交互控件（分段控件、输入框、快捷时长 chip、删除按钮）严格使用绿灰中性色（`--rf-gray-*` / `--rf-bg-*` / `--rf-border*`）；
  - 唯一实心主按钮（听力录入的「记录」按钮）使用 `--rf-accent`（墨绿 `#153a29`，悬停 `#1f4d36`）+ 白字；
  - 热力图与 14 天柱状图统一使用数据绿（`--rf-data`、`--rf-heat-1` ~ `--rf-heat-4`）；
  - **禁止引入紫色，禁止写裸 hex 色值**，全部引用 `tokens.css` 语义变量。
- **字号与字重**：
  - 单一字族 `--rf-font-sans`；
  - 顶部四连卡大数字使用 `text-3xl`（32px）+ `font-extrabold`（800），指标标签使用 `text-sm`（14px）+ `font-normal`（400）+ `--rf-text-secondary`，通过字号、字重与色阶三维拉开对比；
  - 区块标题使用 `text-xl`（20px）+ `font-bold`（700）；
  - **严禁使用 `font-medium`（500）和 `font-black`（900）**，严禁使用半像素字号。

### 6.2 布局、亲密性与去噪
- **容器与对齐**：复用 `.rf-container`（最大宽 1200px，左边缘与顶部导航 Logo 严格对齐）；所有标题、数字、图表标签、列表项统一**左对齐**（不居中堆砌卡片文字）。
- **不嵌套框、静止卡片无阴影**：
  - 卡片统一白底 + `1px solid var(--rf-border)` + `rounded-lg`（16px）+ `p-6`（24px，手机端 `p-4`）；
  - 卡片内部不再套带边框的灰底小框；录入区内部各字段用 `gap-3`（12px）分组，区块之间用 `mb-6`（24px）拉开，遵守「组内间距 < 组间间距」。
- **视觉降噪**：
  - 不使用花哨 emoji 堆砌装饰、不弹鸡汤鼓励横幅；
  - 列表行高度 ≥ 56px，行间用 `1px` 分隔线；听力记录的删除按钮默认隐藏（`opacity-0`），仅在行 `:hover` / `:focus-within`（移动端常显轻量灰图标）时显现。
- **响应式适配**：
  - 桌面端（≥ 1024px）：四连卡 4 列；日历与 14 天柱状图并排；听力手动录入表单单行或紧凑两行铺开；
  - 移动端（< 640px）：四连卡 2×2；日历横向可滚动不撑破屏幕；录入表单自动纵向堆叠，主按钮占满整行方便单手点按。

## 7. 验收标准（Definition of Done）

### 功能验收
1. **阅读统计准确性**：导入一篇 500 词文章，未点「标记已读完」前，今日与累计读懂词数均为 `0`；点击「标记已读完」后，刷新 `/stats` 今日与累计均增加 `500 词`，柱状图与热力图对应日期点亮；取消标记后，词数实时回退。
2. **网页摘录排除**：通过浏览器插件收集的网页单句摘录（`sourceType = 'web'`）不计入阅读词数与已读完篇数。
3. **听力录入闭环**：在 `/stats?tab=listening` 输入 `15` 分钟并提交，页面无报错且即时更新「今日听懂时长」「累计听懂时长」、柱状图、热力图与最近记录列表；刷新页面数据持久化保留。
4. **听力记录删除**：删除一条已录入的听力记录后，当日与累计时长同步扣减，数据一致。
