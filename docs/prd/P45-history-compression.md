# PRD：追问上下文压缩

| 项 | 内容 |
|---|---|
| 编号 | P45 |
| 状态 | 已确认（2026-11-19，产品逐条确认） |
| 依赖 | **P26**（对话串、多轮追问）、**P44**（对话式右栏） |
| 配套文档 | 实现说明 `docs/specs/P45-history-compression.md` |

## 1. 背景与问题
同一处批注上可以一直追问，每一轮都要把之前的问答带给模型。原来的做法是只留最近 12 轮、每条回答砍掉尾部：
1. 轮数一多，**最先被丢掉的是首次讲解**，也就是最重要的那一轮；
2. 回答被砍的是尾部，而尾部常有结论；
3. 历史里还带着「制卡建议」行、句子地图这类对后面没用的内容；
4. 学生在输入框里打的问题**没有长度上限**。

## 2. 目标与非目标
- 目标：对话再长，请求大小也有上限；首次讲解和最近几轮不失真；用户知道哪些对话已被压缩。
- 非目标：**这一期不做「模型摘要」**（用户 2026-11-19 决定）。以后如果发现压成要点后追问质量明显下降，再考虑超过 20 轮时才触发一次模型摘要。

## 3. 功能需求
- **F1 三档：** 首次讲解（第 1 轮）一直完整保留；最近 3 轮完整保留；中间更早的每一轮压成「要点」（学生的问题 + 回答开头约 300 字）。
- **F2 按位置压缩：** 同一轮一旦变成要点就一直是要点，每次请求的前缀不变，模型缓存仍能命中。
- **F3 清理：** 所有历史回答都去掉末尾的「制卡建议」行和句子地图行；单条回答最多 2000 字，超出从中间截（保留头尾）。
- **F4 预算兜底：** 历史总量按估算 6000 token 限制，超了先丢最早的要点，再缩短近期几轮，最后才缩短首次讲解。有整轮被丢掉时，告诉模型「更早的 N 轮对话已省略」。
- **F5 用户提示：** 对话里一旦有轮次被压缩，在第一条被压缩的对话上面显示一行很淡的小字：「以下较早的对话已压缩：AI 只参考要点（首次讲解和最近 3 轮仍是完整的）」；有整轮被丢掉时加「；最早的 N 轮已不再参考」。对话还短（首次讲解 + 最近 3 轮以内）时不显示。
- **F6 提问长度：** 学生一次提问最多 500 字（输入框限制，服务端也截断）。

## 4. 已确认的决策
| # | 决策 |
|---|---|
| D1 | 压缩用规则，不额外调用模型；这一期不做模型摘要 |
| D2 | 必须在界面上提示用户有对话被压缩 |
